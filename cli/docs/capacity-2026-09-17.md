# Mac 동시 처리 검증 — 2026-09-17

이번 단계는 일반적인 짧은 요청에서 **초당 1–2건**, 관리 모델 합산 **평균 4 GiB**를 목표로 한다. 최대 길이 입력에도 같은 처리량을 보장하는 SLA는 아니다.

## 적용 정책

| 항목 | 결정 |
| --- | --- |
| 모델 실행 | embedding 1 + STT 1 동시 실행, 각 모델 내부는 직렬 |
| 요청 수용 | profile당 실행 1 + 대기 3. 초과/5초 대기 만료는 429 |
| Relay Pipe | profile당 기본 8. 모델 수용 한도와 완료 연결 정리 여유를 분리 |
| 메모리 목표 | 관리 Python + Rust supervisor 합산 최근 60초 표본 평균 4 GiB |
| 비상 보호선 | 합산 5.5 GiB 이상 신규 추론 거부, 6 GiB 초과 관측 시 모델 종료 |
| 유지 | 입력 한도, cache 64 MiB/profile, 자동 replay 없음, 소유 프로세스 종료·cache lease |

평균 목표를 순간 상한으로 해석해 넣었던 home 전체 추론 lock을 profile별로 나눴다. 짧은 대기열이 요청 폭증을 흡수한다. 8건을 수용하는 것이 모델 8개를 병렬 실행한다는 뜻은 아니다. 비상선은 OS 강제 상한이나 호스트 전체 메모리 압력 감지가 아니다.

## 측정 조건

- Apple M3 Max / 36 GiB 개발용 Mac, 고정 Qwen3 Embedding 0.6B 8bit + Qwen3 ASR 0.6B 4bit.
- warmup 후 임베딩 4문서·648토큰과 영어 합성 음성 WAV 3.084초를 1:1로 호출. 각 동시성 30회 wave, 모든 응답 후 다음 wave 시작.
- 직접 loopback과 Docker Compose LLMGate → Caller → TLS RelayGate → MLX 비교. 평균/peak는 250ms physical footprint 표본, Docker·설치·개발 도구 제외.
- 성공 응답 기준 req/s·p95. 공유 개발 호스트의 단일 실행 결과이며 장비의 보장 처리량이나 독립된 정밀 성능 비교는 아니다.

## LLMGate 경유 결과

| 동시 요청 | 이전 성공/전체 | 최종 성공/전체 | 최종 성공 req/s | 최종 p95 | 평균 / peak GiB |
| --- | --- | --- | --- | --- | --- |
| 1 | 30/30 | 30/30 | 8.64 | 0.140초 | 2.17 / 2.24 |
| 2 | 30/60 | 60/60 | 10.70 | 0.196초 | 2.33 / 2.59 |
| 4 | 30/120 | 120/120 | 11.09 | 0.365초 | 2.31 / 2.59 |
| 8 | 30/240 | 240/240 | 11.38 | 0.710초 | 2.35 / 2.60 |

직접 경로와 경유 경로 모두 최종 450/450 성공했다. 이전(`c07363b`) 동시성 2에서는 임베딩이 공용 lock을 선점해 STT 30건이 모두 거부됐다. 경유 호출의 반복 429는 기존 회로 차단을 열어 502와 약 31초 회복 지연으로 이어졌다. 대기열 한도를 넘는 과부하의 서버 회로 차단 정책은 이번에 변경하지 않았다.

별도 실험 중 4 Pipe 설정에서 일시적인 upstream 503도 관측했다. 당시 분류 로그가 없어 그 원인을 확정할 수 없다. 최종 기본값은 완료 연결 정리 여유를 둔 8이고, Caller는 토큰·진단 문자열 없이 SDK 오류 코드/관측 분류만 기록한다. 최종 900건 wave + 2,056건 지속 부하에서는 재발하지 않았다.

## 지속 부하·안전장치

- 같은 추론 정책의 1차 5분 혼합 부하(동시 요청 2): **2,396건 성공**, 7.98 req/s, p95 0.467초, 평균 2.32 GiB, 모델 재시작 0. 이 단계의 Pipe 상한은 4였다.
- 최종 3분 부하(동시 요청 8, Pipe 상한 8): **2,056/2,056 성공**, 11.37 req/s, p95 0.730초, 평균 2.39 GiB / peak 2.70 GiB, 재시작 0. 앞선 wave 검사 900건도 모두 성공. 부하 중 Caller dial 오류 없음(등록 전 의도한 NotFound 1건 제외).
- 전체 검증의 관측 peak는 **3.60 GiB**. 기존 host swap은 증가하지 않았다. 부하 후 직접/경유 평균 지연은 각각 0.208/0.218초로, 지연 변동이 전달 경로에만 국한되지는 않았다. 원인을 열 제한으로 단정하지 않는다.
- 최대 입력 8,192토큰 임베딩 + 60초 음성 동시 호출 **2.298초**에 성공. 긴 음성은 합성 음성 반복이며 실제 자연 음성 정확도 검증이 아니다.
- 요청 body 전송 후 50ms에 소켓 종료 → 후속 정상 요청으로 embedding·STT JSON/SSE 슬롯 회복을 각각 1.658/1.076/0.389초에 확인. GPU 작업의 즉시 취소 보장은 아니다.
- CLI Rust 2개, Caller Rust 1개, Python 22개 테스트: profile 분리, 대기열 초과·만료·취소 회복, 평균 목표와 비상선 구분, PID 재사용·프로세스 정리·UX.

배치 확대/캐시 확대는 목표 달성에 필수적이지 않아 제출 코드에서 제외했다. 여러 물리 Mac, 8/16 GiB Mac, 30–60분 열 안정성, 다양한 실제 음성은 별도 검증이 필요하다. 공개 배포/운영 rollout을 의미하지 않는다.

## 재현

```sh
cd cli
scripts/package-macos.sh
.local/test-env/bin/python scripts/e2e_macos.py \
  --cli-binary target/aarch64-apple-darwin/release/llmgate-cli \
  --benchmark --soak-seconds 180 --soak-concurrency 8 --verify-limits
```

Docker·로컬 Gateway build·테스트 의존성이 필요하다. 기존 등록/실행 중 home은 덮어쓰지 않는다. `.local/e2e-embedding-stt/{benchmark,capacity-results,limits-results}.json`에 키 없이 결과를 저장하며 실패한 실행의 이전 결과가 남지 않게 초기화한다. 이전 버전의 거절률 비교에는 `--allow-benchmark-rejections`를 추가한다.
