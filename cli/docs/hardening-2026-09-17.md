# Mac 워커 장애 복구 보강 검증

| 항목 | 변경·검증 |
| --- | --- |
| 슬롯 소유권 | executor 실제 완료 시 반환. 반복 취소·제출 실패·STT 파일 닫기/캐시 정리/잠금 획득 실패 주입 검증 |
| 추론 정지 | 슬롯 점유 120초 이상이면 health 실패. 시간 경계 단위 테스트 + 실제 Rust 감독의 unhealthy 모델 교체 테스트. health 주기 10초·요청 3초 및 연결 정리·프로세스 종료 대기가 추가됨 |
| 과부하 | 명시적 `worker_capacity` 429만 회로 차단·자동 fallback 제외. 일반 제공자 429 유지 |
| 실제 과부하 복구 | Docker LLMGate → Caller → RelayGate → MLX에서 모델별 연속 429 5회 후 즉시 200 |
| 로그 | 모델·감독 로그 모두 10MiB × 현재 포함 5개. 크기 회전과 쓰기 실패 누락 집계 테스트 |
| 실제 호출 | 임베딩 float/base64, STT JSON/SSE 통과 |
| 장애 복구 | 토큰 만료·Gateway 재시작·클라이언트 연결 끊김 후 성공. 테스트 종료 후 프로세스·runtime·등록 정리 확인 |
| 혼합 부하 | Apple M3 Max, 동시 호출 2, 60.15초, 654/654 성공, 10.873 req/s, p95 0.227초, 평균 2.272GiB·peak 2.601GiB |
| 최대 입력 | 합계 8,192토큰 임베딩 + 60초 음성 동시 호출 2.177초 성공 |

짧은 텍스트·약 3초 테스트 음성 기반 수치다. 최대 길이 입력의 처리량 SLA, 장시간 안정성, 여러 물리 Mac 검증을 의미하지 않는다. GPU를 실제로 영구 정지시킨 검증은 하지 않았으며, 시간 초과 판정과 감독 프로세스 교체를 분리 검증했다. Python 라이브러리 출력 전체의 비밀정보 제거도 보장하지 않는다.
